### 2.3 MessagePopover 표시 방식

유효성 검증 오류는 Begin Column Footer의 `sap.m.MessagePopover`로 표시한다.

납기지연 및 미입고 현황 조회 프로그램과 UX를 맞추기 위해 Footer 버튼은 다음 방식으로 표시한다.

| 항목 | 현재 기준 |
|---|---|
| Footer 버튼 표시 | 오류 아이콘 + 숫자만 표시 |
| 예시 | 오류 1건이면 아이콘 옆에 `1`만 표시 |
| 긴 문장 표시 | Footer 버튼에는 표시하지 않음 |
| 메시지 본문 | MessagePopover 내부에 표시 |

현재 i18n 문구는 납기지연 프로그램과 최대한 맞췄다.

```properties
validationMessageButtonTooltip=조회조건 메시지
validationErrorCount={0}
validationMessageDescription=메시지를 선택하면 해당 조회조건으로 이동합니다.
validationDateFormatInvalid=날짜 입력 필드는 yyyy-MM-dd 형식으로 입력해야합니다.
validationDocDateRangeInvalid=문서일자 From은 문서일자 To보다 늦을 수 없습니다.
validationEindtRangeInvalid=납기일 From은 납기일 To보다 늦을 수 없습니다.
validationDateBeforeCompanyStart=회사 설립일(2020-03-15)보다 과거 날짜는 입력하실 수 없습니다.
validationCodeNotFound={0}에 존재하지 않는 값입니다.
validationTechnicalError=조회조건 검증 중 오류가 발생했습니다.
```

### 2.4 초기화 버튼 수정

초기화 버튼 문제를 수정했다.

원인은 `DatePicker`에 잘못된 날짜 문자열을 직접 입력한 경우, 해당 값이 `dateValue` 모델에는 반영되지 않고 컨트롤 내부 `value`에만 남을 수 있었기 때문이다.

수정 내용은 다음과 같다.

| 항목 | 수정 내용 |
|---|---|
| filter 모델 | 기존 모델을 `setData()`로 초기화 |
| 바인딩 | `updateBindings(true)` 호출 |
| Input | 실제 화면 표시값도 `setValue("")`로 초기화 |
| DatePicker | `setDateValue(null)` + `setValue("")` 모두 수행 |
| MultiComboBox | `setSelectedKeys([])`로 초기화 |
| MessagePopover | 오류 메시지 모델 초기화 |
| ValueState | 오류 상태 제거 |

### 2.5 플랜트 입력 길이 수정

플랜트코드는 프로젝트 기준으로 `P00001`처럼 6자리다.

확인 결과 OData metadata는 이미 `MaxLength="6"`으로 되어 있었고, View의 Input만 `maxLength="4"`로 남아 있었다.

수정 내용:

| 파일 | 수정 |
|---|---|
| `webapp/view/Main.view.xml` | `idWerksInput`의 `maxLength`를 `4`에서 `6`으로 변경 |
| 추가 구현 설계서 | 플랜트 4자리 설명을 6자리 기준으로 보정 |
