## 1. 개발 목적

본 프로그램은 하나의 RFQ(Request for Quotation)에 대해 여러 공급업체가 제출한 MQ 견적을 시각적으로 비교하고, 가격과 납기 기준으로 최적의 견적을 채택한 뒤 PO(Purchase Order)까지 생성하기 위해 개발한 SAP Fiori 프로그램이다.

생산에 필요한 자재가 확인되어도 어느 공급업체가 얼마에, 언제까지 납품할 수 있는지 빠르게 결정하지 못하면 실제 구매 실행과 생산 투입 시점이 지연될 수 있다. 기존 구매 업무에서는 공급업체별 견적금액, 통화, 환율, 가격단위와 납기일을 개별적으로 확인해야 했기 때문에 최적 거래선을 선정하는 데 시간이 걸렸다.

본 프로그램은 RFQ 조회, MQ 비교, 오늘 기준 환율을 적용한 KRW 환산, 납기 준수 여부 확인, 자동추천, 거래선 채택 및 PO 생성을 하나의 Fiori 업무 흐름으로 연결한다. 이를 통해 필요한 자재의 공급업체와 납기를 신속하게 확정하고, 비즈니스 챌린지 **1-2의 생산계획 수립 시 조달 가능성 반영 부족 문제를 완화하는 데 기여**하는 것을 목적으로 한다.

| 기존 문제 | 해결 방식 |
| --- | --- |
| RFQ에 여러 공급업체가 응답하여 가격과 납기를 한눈에 비교하기 어려움 | MQ 비교 테이블과 Bar Chart를 통해 공급업체별 견적을 시각화 |
| 외화 견적과 가격단위가 달라 단가만으로 실제 구매비용 비교가 어려움 | 오늘 기준 적용환율과 가격단위를 반영한 KRW 환산총액으로 비교 |
| 가격이 낮아도 요청 납기일을 지키지 못하는 견적을 선택할 위험이 있음 | RFQ 요청 납기일을 준수하는 MQ만 자동추천 대상으로 제한 |
| 구매 담당자가 최적 공급업체를 수작업으로 판단해야 함 | 납기를 준수하면서 KRW 환산총액이 가장 낮은 공급업체를 자동추천 |
| 채택 이후 PO 생성까지 업무가 분리되어 구매 실행이 지연됨 | 채택된 MQ를 기준으로 PO Header/Item을 일괄 생성 |
| 이미 PO가 생성된 견적을 변경하거나 다시 생성할 위험이 있음 | UI 버튼 비활성화와 Backend `QTNFN/QTNFP` 중복 검증을 함께 적용 |
| 코드 입력 오류로 잘못된 조회조건이 전달될 수 있음 | CDS OData 기반 Search Help 및 코드 존재 여부 유효성 검증 적용 |
| 처리 결과와 오류 원인을 즉시 확인하기 어려움 | Footer `MessagePopover`로 검증 오류와 업무 처리 결과를 표시 |

포트폴리오 요약 문장:

> SAPUI5와 Gateway OData를 활용하여 하나의 RFQ에 접수된 여러 공급업체 견적을 가격과 납기 기준으로 비교하고, 오늘 기준 환율을 적용한 KRW 환산총액과 납기 준수 여부를 기반으로 최적 거래선을 추천했습니다. 채택된 견적은 PO 생성까지 연결하여 자재의 공급업체와 납기를 빠르게 확정할 수 있도록 구현했습니다.

## 2. 해결해야 할 비즈니스 챌린지

### 2.1 대상 비즈니스 챌린지

본 프로그램이 해결하는 핵심 비즈니스 챌린지는 **1-2. 생산계획 수립 시 실제 자재 가용 수량이 충분히 반영되지 않아 계획 대비 생산 차질이 발생하는 문제**이다.

본 프로그램이 현재고나 MRP를 직접 계산하는 것은 아니다. 그러나 생산에 필요한 자재가 확인된 이후 실제 조달 가능성을 확보하려면, 공급업체와 구매가격 및 납기일이 확정되고 PO가 생성되어야 한다. 따라서 견적 비교와 거래선 채택을 신속하게 수행하는 기능은 생산계획에 필요한 자재의 조달 가능성을 높이는 데 기여한다.

### 2.2 비즈니스 챌린지 1-2 해결 근거

| 문제 상황 | 프로그램의 해결 방식 | 생산계획에 대한 기여 |
| --- | --- | --- |
| 필요한 자재가 확인되어도 공급업체를 빠르게 선정하지 못함 | 하나의 RFQ에 접수된 여러 공급업체 MQ를 한 화면에서 비교 | 자재 공급업체 확정시간 단축 |
| 공급업체별 통화와 가격단위가 달라 실제 구매비용 판단이 어려움 | 오늘 기준 환율과 가격단위를 반영한 KRW 환산총액 제공 | 동일한 기준으로 구매비용을 비교하여 의사결정 지연 완화 |
| 가격이 낮아도 생산 요구일보다 납기가 늦은 견적을 선택할 수 있음 | RFQ 요청 납기일을 준수하는 MQ만 자동추천 대상으로 선정 | 생산 일정에 맞는 조달 가능성 확보 |
| 구매 담당자가 가격과 납기를 수작업으로 비교함 | 납기 준수 MQ 중 환산총액 최저가를 자동추천 | 거래선 선정시간 단축 |
| 거래선 채택과 PO 생성이 분리되어 구매 실행이 지연됨 | 채택된 MQ를 기반으로 PO를 일괄 생성 | 선정 결과를 실제 구매 실행으로 즉시 연결 |
| 이미 생성된 PO를 중복 생성하거나 채택 견적을 변경할 수 있음 | PO 참조 중복 검증 및 PO 생성 후 채택 변경 차단 | 자재 조달 문서의 정합성 유지 |


따라서 비즈니스 챌린지 1-2를 단독으로 완전히 해결한다고 표현하기보다는, 다음과 같이 설명하는 것이 정확하다.

> 생산에 필요한 자재의 현재고와 가용수량은 별도의 재고 및 MRP 프로그램에서 판단하고, 본 프로그램은 부족 자재에 대한 공급업체, 구매가격과 납기일을 빠르게 확정하여 실제 조달 가능성을 높이는 역할을 담당합니다.

### 시연1: RFQ 조회와 공급업체 견적 시각화

1. 이전에 생성한 RFQ 번호를 Search Help에서 선택한다.
2. 조회 버튼을 누르면 RFQ 1건이 조회되고 FlexibleColumnLayout의 Mid 컬럼이 자동으로 열린다.
3. RFQ Item을 선택하면 해당 Item에 응답한 공급업체의 MQ 목록이 조회된다.
4. 오늘 기준 환율이 적용된 KRW 환산총액이 Bar Chart와 비교 테이블에 표시되는 것을 확인한다.

### 시연2: 자동추천과 거래선 채택

1. `자동추천` 버튼을 누른다.
2. RFQ 요청 납기일을 충족하는 MQ 중 KRW 환산총액이 가장 낮은 공급업체가 선택되는 것을 확인한다.
3. `채택` 버튼을 눌러 최종 거래선으로 저장한다.
4. RFQ Header, RFQ Item, MQ 비교목록과 차트가 최신 상태로 재조회되는 것을 확인한다.

### 시연3: 채택 견적 기반 PO 일괄 생성

1. Footer의 `PO 생성` 버튼을 누른다.
2. 하나의 RFQ에 대해 채택된 견적을 기반으로 PO가 일괄 생성되는 것을 확인한다.
3. 이미 PO 생성된 Item과 미채택 Item은 생성 대상에서 제외된다.
4. 회사코드, 구매조직, 구매그룹, 공급업체, 지급조건과 통화 기준으로 PO Header가 나뉘는 것을 설명한다.
5. 생성된 PO 번호와 Item 수를 Footer MessagePopover에서 확인한다.
6. 생성된 PO 번호는 후속 송장검증 등 구매 프로세스에서 사용할 수 있다.

## 4. 주요 코드

> 아래 코드 블록의 실행문, 조건식, 속성값과 메시지 문구는 현재 UI5 소스 및 전달받은 DPC_EXT Class 원문에서 그대로 발췌했다. 포트폴리오 설명에 필요하지 않은 연속 구간만 언어별 주석의 `(중략)`으로 표시했다.

### 4.1 RFQ 조회와 KPI 갱신

#### Frontend: RFQHeaderSet 조회

```javascript
/**
 * RFQHeaderSet을 조회하여 Begin Column의 RFQ Header 목록, KPI, 건수를 갱신한다.
 *
 * SAPUI5 OData V2 Model의 `read`는 success/error 콜백 방식이다.
 * 이 화면에서는 조회 이후 여러 후속 처리가 이어지므로 `_readEntitySet`에서 Promise로 감싼 뒤
 * then/catch/finally 흐름으로 작성한다.
 *
 * @param {object} mOptions RFQ Header 재조회 방식을 제어하는 선택 옵션
 * @param {boolean} mOptions.keepComparisonContext
 *        true이면 채택 또는 PO 생성 후에도 현재 선택 RFQ와 Mid Column을 유지한다.
 * @returns {Promise<object[]>} Backend에서 조회한 RFQ Header 배열
 */
_loadRfqHeaders(mOptions = {}) {
    // oView: 현재 Main View 객체
    const oView = this.getView();

    // oViewModel: Busy 상태와 FlexibleColumnLayout 상태 등 화면 제어값을 관리하는 JSONModel
    const oViewModel = oView.getModel("view");

    // oWorkModel: RFQ Header, RFQ Item, MQ 비교 결과 등 업무 데이터를 관리하는 JSONModel
    const oWorkModel = oView.getModel("work");

    // aFilters: 화면 조회조건을 OData $filter 조건으로 변환한 배열
    const aFilters = this._buildHeaderFilters();

    // bKeepComparisonContext: 재조회 후에도 사용자가 보고 있던 비교 화면을 유지할지 여부
    const bKeepComparisonContext = mOptions.keepComparisonContext === true;

    if (oViewModel) {
        oViewModel.setProperty("/Busy", true);
    }

    /*
     * 일반 조회는 이전 비교 컨텍스트를 지우지만, 채택 후 재조회는 사용자가 보던
     * Mid Column과 선택 RFQ Item을 유지해야 하므로 초기화를 건너뛴다.
     */
    if (!bKeepComparisonContext) {
        this._clearSelectionAndComparisonArea();
    }

    return this._readEntitySet("/RFQHeaderSet", aFilters).then((aRows) => {
        // aRows: RFQHeaderSet GET 요청으로 Backend에서 반환받은 RFQ Header 목록
        oWorkModel.setProperty("/RfqHeaders", aRows);
        this._applyHeaderQuickAwardStatusFilter("", true);
        this._updateHeaderKpis(aRows);
        this._reapplyHeaderTableSorters();

        if (!bKeepComparisonContext && aRows.length === 1) {
            /*
             * RFQ 번호로 1건만 조회된 경우에는 사용자가 목록을 다시 누르지 않아도 Mid Column을 연다.
             * Header 조회 자체는 성공으로 유지해야 하므로, Item 조회 실패는 RFQHeaderSet catch로 전파하지 않는다.
             */
            this._openMidColumnForRfq(aRows[0]).catch(() => {});
        }

        return aRows;
    }).catch((oError) => {
        // oError: RFQHeaderSet 조회 실패 시 OData Model이 전달한 오류 객체
        oWorkModel.setProperty("/RfqHeaders", []);
        this._applyHeaderQuickAwardStatusFilter("", true);
        this._updateHeaderKpis([]);
        this._showToast(this._getText("msgLoadRfqHeaderError") || "RFQ Header 조회 중 오류가 발생했습니다.");
        throw oError;
    }).finally(() => {
        if (oViewModel) {
            oViewModel.setProperty("/Busy", false);
        }
    });
}
```

#### Backend: RFQ Header와 조직명 조회

```abap
    "------------------------------------------------------------------
    " [3] RFQ Header 기본정보 조회
    "------------------------------------------------------------------
    " ZTD3MM0016은 구매문서 Header 테이블이다.
    " BSART = 'RQ'인 문서만 RFQ Header로 본다.
    "
    " 회사명, 구매조직명, 구매담당자명은 마스터 테이블을 LEFT JOIN하여
    " 조회한다. 마스터가 없어도 RFQ 자체는 표시되어야 하므로
    " INNER JOIN이 아니라 LEFT OUTER JOIN을 사용한다.
    "------------------------------------------------------------------
    " Alias 설명:
    " - RQH : RFQ Header
    " - CC  : 회사코드 및 회사명 마스터

    " - LS_FILTER : UI5 OData $filter를 ABAP 필드로 변환한 조회조건 구조
    " - LT_HEADER : RFQ Header 조회 결과와 KPI 계산의 기준이 되는 Internal Table
    "
    " LS_FILTER Component:
    " - LS_FILTER-RFQ_NO  : RFQ 번호 조회조건
    " - LS_FILTER-DOC_FROM: RFQ 문서일자 시작 조건
    " - LS_FILTER-DOC_TO  : RFQ 문서일자 종료 조건
    " - LS_FILTER-BUKRS   : 회사코드 조회조건
    " - LS_FILTER-EKORG   : 구매조직 조회조건
    " - LS_FILTER-EKGRP   : 구매그룹 조회조건
    "------------------------------------------------------------------
SELECT
  FROM ztd3mm0016 AS rqh
  LEFT OUTER JOIN ztd3fi0002 AS cc
    ON cc~bukrs = rqh~bukrs
  LEFT OUTER JOIN ztd3mm0012 AS org
    ON org~ekorg = rqh~ekorg
  LEFT OUTER JOIN ztd3mm0013 AS grp
    ON grp~ekgrp = rqh~ekgrp
  " RFQ 번호, 문서일자와 구매조직 명칭을 Header 결과에 적재한다.
  FIELDS rqh~ebeln AS rfq_no,
         rqh~bedat AS doc_date,
         rqh~bukrs,
         cc~butxt,
         rqh~ekorg,
         org~ekotx,
         rqh~ekgrp,
         grp~eknam,
         rqh~waers
  " BSART='RQ'이고 삭제되지 않은 RFQ 중 입력된 조회조건에 맞는 문서만 조회한다.
  WHERE rqh~bsart = 'RQ'
    AND rqh~lvorm = @space
    AND ( @ls_filter-rfq_no   IS INITIAL OR rqh~ebeln = @ls_filter-rfq_no )
    AND ( @ls_filter-doc_from IS INITIAL OR rqh~bedat >= @ls_filter-doc_from )
    AND ( @ls_filter-doc_to   IS INITIAL OR rqh~bedat <= @ls_filter-doc_to )
    AND ( @ls_filter-bukrs    IS INITIAL OR rqh~bukrs = @ls_filter-bukrs )
    AND ( @ls_filter-ekorg    IS INITIAL OR rqh~ekorg = @ls_filter-ekorg )
    AND ( @ls_filter-ekgrp    IS INITIAL OR rqh~ekgrp = @ls_filter-ekgrp )
  " SELECT Alias와 동일한 Component명을 기준으로 LT_HEADER에 결과를 적재한다.
  INTO CORRESPONDING FIELDS OF TABLE @lt_header.

 " 조회 결과가 없으면 후속 Item/MQ/PO 상태 계산 없이 빈 EntitySet을 반환한다.
IF lt_header IS INITIAL.
  RETURN.
ENDIF.

" (중략) RFQ Item, MQ, PO 상태를 조회하여 Header별 건수와 채택상태를 계산한다.
```

### 4.3 MQ 비교, 환율 적용 및 자동추천

#### Frontend: 비교 목록과 차트 데이터 동시 구성

```javascript
/**
 * 선택 RFQ Item의 MQCompareSet을 조회한다.
 *
 * DPC_EXT는 RFQ 번호와 RFQ Item 번호를 함께 받아야 후보 MQ를 정확히 비교할 수 있다.
 * 조회된 Row에는 RadioButton 바인딩용 UI 전용 필드 `UiSelected`를 false로 추가한다.
 * 실제 선택 가능 여부는 Backend의 `CanSelect`를 그대로 사용하고, 여기서는 자동 선택하지 않는다.
 *
 * @param {object} oRfqItem 사용자가 선택한 RFQ Item 데이터
 * @returns {Promise<object[]>} KRW 환산총액 오름차순으로 정렬된 MQ 비교 Row 배열
 */
_loadMqCompareForRfqItem(oRfqItem) {
    // oView: 현재 Main View 객체
    const oView = this.getView();

    // oWorkModel: 선택 RFQ, MQ 비교표와 차트 데이터를 관리하는 업무 JSONModel
    const oWorkModel = oView.getModel("work");

    // oSelectedRfq: 현재 Mid Column에서 작업 중인 RFQ Header
    const oSelectedRfq = oWorkModel ? (oWorkModel.getProperty("/SelectedRfq") || {}) : {};

    // sRfqNo: MQ 후보를 조회할 원본 RFQ 번호
    const sRfqNo = oRfqItem && (oRfqItem.RfqNo || oSelectedRfq.RfqNo);

    // sRfqItem: MQ 후보를 조회할 원본 RFQ Item 번호
    const sRfqItem = oRfqItem && oRfqItem.RfqItem;

    // aFilters: MQCompareSet에 전달할 RFQ 번호와 RFQ Item OData Filter 배열
    const aFilters = this._buildMqCompareFilters(sRfqNo, sRfqItem);

    if (!sRfqNo || !sRfqItem) {
        return Promise.resolve([]);
    }

    return this._readEntitySet("/MQCompareSet", aFilters).then((aRows) => {
        // aRows: Backend MQCompareSet에서 반환한 원본 MQ 비교 Row 배열

        // aPreparedRows:
        // Backend 결과에 UI 전용 선택상태를 추가하고 KRW 환산총액 오름차순으로 정렬한 배열
        const aPreparedRows = this._sortMqCompareRowsByNetwrKrw((aRows || []).map((oRow) => Object.assign({}, oRow, {
            // oRow: Backend가 반환한 MQ 후보 한 건
            UiSelected: false
        })));

        if (oWorkModel) {
            oWorkModel.setProperty("/MqCompareRows", aPreparedRows);
            oWorkModel.setProperty("/ChartRows", this._prepareChartRows(aPreparedRows));
        }

        return aPreparedRows;
    }).catch((oError) => {
        // oError: MQCompareSet 조회 실패 시 OData Model이 전달한 오류 객체
        if (oWorkModel) {
            oWorkModel.setProperty("/MqCompareRows", []);
            oWorkModel.setProperty("/ChartRows", []);
        }

        this._showToast(this._getText("msgLoadMqCompareError") || "MQ 비교 목록 조회 중 오류가 발생했습니다.");
        throw oError;
    });
}
```

```abap
             mqi~peinh,

      " 구매문서 유형이 MM견적(MQ)인 Header만 조회한다.
      WHERE mqh~bsart = 'MQ'
```

#### Frontend: QuotationItemSet MERGE

```javascript
/**
 * 사용자가 지정한 MQ Item을 채택하거나 기존 채택을 취소한다.
 *
 * @param {string} sMqNo 처리 대상 MQ 구매문서 번호
 * @param {string} sMqItem 처리 대상 MQ Item 번호
 * @param {string} sActionType Backend 처리 구분값(AWARD 또는 CANCEL)
 * @param {string} sSuccessMessage 정상 처리 후 MessageToast에 표시할 문구
 * @returns {Promise<object|null>} MERGE 처리와 화면 재조회 결과
 */
_updateQuotationItem(sMqNo, sMqItem, sActionType, sSuccessMessage) {
    // oViewModel: Backend 처리 중 화면 Busy 상태를 제어하는 JSONModel
    const oViewModel = this.getView().getModel("view");

    // sPath: QuotationItemSet의 MqNo/MqItem Key를 포함하는 OData Entity 경로
    const sPath = this._createQuotationItemPath(sMqNo, sMqItem);

    // oPayload: UPDATE_ENTITY에 전달할 MQ Key와 업무 처리 유형
    const oPayload = {
        MqNo: sMqNo,
        MqItem: sMqItem,
        ActionType: sActionType
    };

    if (!sPath) {
        return Promise.resolve(null);
    }

    if (oViewModel) {
        oViewModel.setProperty("/Busy", true);
    }

    /*
     * 설계서 기준 채택/취소는 Function Import가 아니라 QuotationItemSet 단건 MERGE다.
     * Gateway가 성공 시 204 No Content를 줄 수 있으므로 success body에 의존하지 않고,
     * 성공 callback 자체를 기준으로 메시지와 재조회를 처리한다.
     */
    return this._updateEntity(sPath, oPayload, {
        merge: true
    }).then(() => {
        // MERGE 성공 후 메시지를 표시하고 Header, Item, MQ, Chart를 재조회한다.
        this._showToast(sSuccessMessage);
        return this._refreshAfterAward();
    }).catch((oError) => {
        // oError: QuotationItemSet MERGE 실패 시 전달되는 OData 오류 객체
        this._showToast(this._getText("msgDefaultError") || "처리 중 오류가 발생했습니다. 잠시 후 다시 시도하세요.");
        throw oError;
    }).finally(() => {
        if (oViewModel) {
            oViewModel.setProperty("/Busy", false);
        }
    });
}
```

```javascript
/**
 * RFQ Item 목록 헤더의 "일괄 채택" 버튼 이벤트.
 *
 * QuotationItemSet 단건 MERGE를 RFQ Item별로 순차 호출하고,
 * 각 Item의 성공/제외/오류 결과를 footer MessagePopover에 표시한다.
 *
 * @returns {Promise<boolean|object>} 사용자 취소 여부 또는 일괄 채택 처리 결과

onBulkAward() {
    // oWorkModel: 선택 RFQ와 RFQ Item 목록을 관리하는 업무 JSONModel
    const oWorkModel = this.getView().getModel("work");

    // oSelectedRfq: 현재 일괄 처리 대상인 RFQ Header
    const oSelectedRfq = oWorkModel ? (oWorkModel.getProperty("/SelectedRfq") || {}) : {};

    // aRfqItems: 선택 RFQ에 속한 전체 RFQ Item 배열
    const aRfqItems = oWorkModel ? (oWorkModel.getProperty("/RfqItems") || []) : [];

    if (!oSelectedRfq.RfqNo) {
        this._setProcessMessages([
            this._createProcessMessage(

                this._getText("msgSelectRfq") || "RFQ를 먼저 선택하세요.",
                this._getText("bulkAward") || "일괄 채택"
            )
        ]);
        this._openProcessMessagePopoverDelayed();
        return Promise.resolve(false);
    }

    return this._confirmAction(
        this._getText("msgConfirmBulkAward") ||
        "선택 RFQ의 미채택 RFQ Item에 대해 자동추천 MQ를 일괄 채택하시겠습니까?"
    ).then((bConfirmed) => {
```

#### Controller: 업무 처리 결과 MessagePopover

```javascript
/**
 * 채택/채택취소 처리 결과 MessagePopover를 반환한다.
 *
 * 검증 MessagePopover와 동일한 `sap.m.MessagePopover` 패턴을 사용하지만,
 * 바인딩 모델은 `processMessages`로 분리한다.
 * 이렇게 하면 조회조건 오류와 업무 처리 결과가 서로 덮어쓰지 않는다.
 *
 * @returns {sap.m.MessagePopover} 업무 처리 결과를 표시할 MessagePopover
 */
_getProcessMessagePopover() {
    // _oProcessMessagePopover:
    // Controller에서 재사용하는 업무 처리 결과용 MessagePopover 인스턴스
    if (!this._oProcessMessagePopover) {
        this._oProcessMessagePopover = new MessagePopover({
            items: {
                // processMessages>/items 배열의 각 Row를 MessageItem으로 표시한다.
                path: "processMessages>/items",
                template: new MessageItem({
                    // type: Success, Warning, Error 등 메시지 상태와 아이콘
                    type: "{processMessages>type}",

                    // title: 사용자가 먼저 확인할 핵심 결과 문구
                    title: "{processMessages>title}",

                    // subtitle: RFQ, MQ, PO 번호 등 처리 대상 식별값
                    subtitle: "{processMessages>subtitle}",

                    // description: 성공 건수, 제외 사유 또는 Backend 오류 상세
                    description: "{processMessages>description}"
                })
            }
        });

        // View가 종료될 때 Popover도 함께 정리되도록 Dependent로 등록한다.
        this.getView().addDependent(this._oProcessMessagePopover);
    }

    return this._oProcessMessagePopover;
}
```

#### Frontend: PoCreateRequestSet POST

```javascript
/**
 * 선택 RFQ 기준 PO 생성 버튼 이벤트.
 *
 * PO Header/Item 생성은 UI5가 직접 계산하지 않고 Backend에 위임한다.
 * 현재 Gateway에서 확정한 API는 Function Import가 아니라
 * `PoCreateRequestSet` EntitySet에 생성 요청을 보내는 CREATE_ENTITY 방식이다.
 *
 * SAPUI5 OData V2 Model의 create 메소드는 지정한 EntitySet에 POST를 보내므로,
 * Gateway Client에서 성공 확인한 `/PoCreateRequestSet` + `{ RfqNo: ... }` 요청과
 * 같은 형태로 동작한다.
 *
 * @returns {Promise<object|null>} Backend PO 생성 응답 또는 실행하지 않은 경우 null
 */
onCreatePoFromRfq() {
    // oView: 현재 Main View 객체
    const oView = this.getView();

    // oViewModel: PO 생성 처리 중 Busy 상태를 제어하는 화면 JSONModel
    const oViewModel = oView.getModel("view");

    // oWorkModel: 선택 RFQ와 PO 생성 가능 여부를 관리하는 업무 JSONModel
    const oWorkModel = oView.getModel("work");

    // oSelectedRfq: 현재 Mid Column에서 선택된 RFQ Header
    const oSelectedRfq = oWorkModel ? (oWorkModel.getProperty("/SelectedRfq") || {}) : {};

    // sRfqNo: Backend PO 생성 요청에 전달할 원본 RFQ 번호
    const sRfqNo = oSelectedRfq.RfqNo;

    if (!sRfqNo) {
        this._showToast(this._getText("msgCreatePoSelectRfq") || "PO를 생성할 RFQ를 먼저 선택하세요.");
        return Promise.resolve(null);
    }

    if (!oWorkModel || !oWorkModel.getProperty("/CanCreatePo")) {
        this._showToast(this._getText("msgCreatePoNoTarget") || "PO를 생성할 수 있는 채택 RFQ Item이 없습니다.");
        return Promise.resolve(null);
    }

    return this._confirmAction(
        this._getText("msgConfirmCreatePo", [sRfqNo]) ||
        "선택 RFQ 기준으로 채택된 MQ를 PO로 생성하시겠습니까?"
    ).then((bConfirmed) => {
        // bConfirmed: PO 생성 확인 MessageBox에서 사용자가 확인을 선택했는지 여부
        if (!bConfirmed) {
            return null;
        }

        if (oViewModel) {
            oViewModel.setProperty("/Busy", true);
        }

        return this._createEntity("/PoCreateRequestSet", {
            RfqNo: sRfqNo
        }).then((oResponse) => {
            // oResponse: 생성 PO 번호, 건수, 제외 건수와 메시지를 포함한 Gateway 응답

            // oMessage: Gateway 응답을 MessagePopover의 MessageItem 형식으로 변환한 객체
            const oMessage = this._createPoCreateProcessMessage(oResponse, sRfqNo);

            // bSuccess: 성공 메시지이고 Backend 오류 건수가 0인지 확인한 결과
            const bSuccess = oResponse && oResponse.MessageType === "S" && Number(oResponse.ErrorCount || 0) <= 0;

            this._setProcessMessages([oMessage]);
            this._openProcessMessagePopoverDelayed();

            /*
             * PO 생성 성공 후에는 Header 상태, RFQ Item 상태, MQ 선택 가능 여부가 바뀐다.
             * 채택/채택취소 후 사용하던 재조회 흐름을 재사용해 Begin/Mid Column을 함께 갱신한다.
             */
            if (bSuccess) {
                return this._refreshAfterAward().then(() => oResponse);
            }

            return oResponse;
        }).catch((oError) => {
            // oError: PoCreateRequestSet POST 실패 시 OData Model이 전달한 오류 객체
            this._setProcessMessages([
                this._createProcessMessage(
                    "Error",
                    this._getODataErrorText(oError),
                    this._getText("createPo") || "PO 생성"
                )
            ]);
            this._openProcessMessagePopoverDelayed();
            throw oError;
        }).finally(() => {
            if (oViewModel) {
                oViewModel.setProperty("/Busy", false);
            }
        });
    });
}
```

```abap
    REFRESH lt_po_group.

    " PO 생성 대상 MQ Item을 한 건씩 읽어 Header 그룹 Key를 구성한다.
    LOOP AT lt_po_target INTO ls_po_target.

      CLEAR ls_po_group.

      " 회사코드
      ls_po_group-bukrs = ls_po_target-bukrs.
      " 구매조직
      ls_po_group-ekorg = ls_po_target-ekorg.
      " 구매그룹
      ls_po_group-ekgrp = ls_po_target-ekgrp.
      " 공급업체코드
      ls_po_group-lifnr = ls_po_target-lifnr.
      " 지급조건
      ls_po_group-zterm = ls_po_target-zterm.
      " 문서통화
      ls_po_group-waers = ls_po_target-waers.

      " 동일한 6개 그룹 Key를 가진 Header 그룹이 이미 존재하는지 확인한다.
      READ TABLE lt_po_group TRANSPORTING NO FIELDS
        WITH TABLE KEY bukrs = ls_po_group-bukrs
                       ekorg = ls_po_group-ekorg
                       ekgrp = ls_po_group-ekgrp
                       lifnr = ls_po_group-lifnr
                       zterm = ls_po_group-zterm
                       waers = ls_po_group-waers.

      IF sy-subrc <> 0.
        " 같은 Key의 그룹이 없을 때만 신규 PO Header 그룹을 추가한다.
        INSERT ls_po_group INTO TABLE lt_po_group.
      ENDIF.

    ENDLOOP.

    " 최종적으로 생성해야 할 PO Header 건수를 계산한다.
    lv_po_group_count = lines( lt_po_group ).

    IF lv_po_group_count = 0.

      ls_response-rfq_no             = ls_request-rfq_no.
      ls_response-message_type       = gc_msg_error.
      ls_response-message_text       = |RFQ { ls_request-rfq_no }의 PO Header 그룹을 생성할 수 없습니다.|.
      ls_response-po_count           = 0.
      ls_response-po_item_count      = 0.
      ls_response-first_po_no        = ''.
      ls_response-created_po_nos     = ''.
      ls_response-skipped_item_count = lv_skipped_count.
      ls_response-error_count        = 1.

      er_entity = ls_response.
      RETURN.

    ENDIF.
```

#### Backend: PO 번호 채번

현재 DPC_EXT 코드 기준 Number Range는 `ZNRD3MM01`, Interval `02`를 사용한다.

```abap
*--------------------------------------------------------------------*
* [10] PO Header 그룹별 PO 번호 채번
*--------------------------------------------------------------------*
* NUMBER_GET_NEXT는 호출 즉시 번호가 소모된다.
* 따라서 RFQ/MQ/필수값/중복 검증이 모두 끝나고,
* 실제 생성할 PO Header 그룹 수가 확정된 뒤에만 호출한다.
*
* 주요 변수와 상수:
* - LT_PO_GROUP       : 번호를 부여할 PO Header 그룹 목록
* - LS_PO_GROUP       : 현재 번호를 부여하는 PO Header 그룹
* - GC_NR_OBJECT      : PO 번호용 Number Range Object 'ZNRD3MM01'
* - GC_NR_INTERVAL    : PO 번호용 Number Range Interval '02'
* - LV_NR_NUMBER      : NUMBER_GET_NEXT가 반환한 다음 순번
* - GC_BSART_PO       : 최종 PO 번호 앞에 붙는 구매문서 유형 'PO'
* - LV_FIRST_PO_NO    : UI5 응답에 전달할 첫 번째 생성 PO 번호
* - LV_CREATED_PO_NOS : 생성된 전체 PO 번호를 연결한 문자열
* - LS_REQUEST-RFQ_NO : PO 생성 요청의 원본 RFQ 번호
* - LS_RESPONSE       : Number Range 오류를 UI5에 반환할 OData 응답 구조
* - GC_MSG_ERROR      : 오류 메시지 유형
* - LV_SKIPPED_COUNT  : 기존 PO 등의 사유로 제외된 RFQ Item 수
* - ER_ENTITY         : Gateway 단건 응답 반환 Parameter
* - SY-SUBRC          : NUMBER_GET_NEXT 실행 결과 코드
*
* LS_PO_GROUP Component:
* - LS_PO_GROUP-PO_NO : 현재 Header 그룹에 부여한 최종 PO 번호
*
* LS_RESPONSE Component:
* - LS_RESPONSE-RFQ_NO             : 처리 대상 RFQ 번호
* - LS_RESPONSE-MESSAGE_TYPE       : 오류 메시지 유형
* - LS_RESPONSE-MESSAGE_TEXT       : Number Range 오류 상세 문구
* - LS_RESPONSE-PO_COUNT           : 생성 PO Header 수
* - LS_RESPONSE-PO_ITEM_COUNT      : 생성 PO Item 수
* - LS_RESPONSE-FIRST_PO_NO        : 첫 번째 생성 PO 번호
* - LS_RESPONSE-CREATED_PO_NOS     : 생성 PO 번호 목록
* - LS_RESPONSE-SKIPPED_ITEM_COUNT : 제외된 RFQ Item 수
* - LS_RESPONSE-ERROR_COUNT        : 오류 건수
*--------------------------------------------------------------------*
    LOOP AT lt_po_group INTO ls_po_group.

      " 이전 그룹에서 사용한 순번을 초기화한다.
      CLEAR lv_nr_number.

      " Number Range Object와 Interval을 기준으로 다음 PO 순번을 요청한다.
      CALL FUNCTION 'NUMBER_GET_NEXT'
        EXPORTING
          nr_range_nr             = gc_nr_interval
          object                  = gc_nr_object
        IMPORTING
          number                  = lv_nr_number
        EXCEPTIONS
          interval_not_found      = 1
          number_range_not_intern = 2
          object_not_found        = 3
          quantity_is_0           = 4
          quantity_is_not_1       = 5
          interval_overflow       = 6
          buffer_overflow         = 7
          OTHERS                  = 8.

      IF sy-subrc <> 0.

        " Number Range 설정 또는 범위 오류가 발생하면 DB 저장 전에 처리를 종료한다.
        ls_response-rfq_no             = ls_request-rfq_no.
        ls_response-message_type       = gc_msg_error.
        ls_response-message_text       = |PO 번호 채번 중 오류가 발생했습니다. Number Range { gc_nr_object }/{ gc_nr_interval }, Subrc { sy-subrc }.|.
        ls_response-po_count           = 0.
        ls_response-po_item_count      = 0.
        ls_response-first_po_no        = ''.
        ls_response-created_po_nos     = ''.
        ls_response-skipped_item_count = lv_skipped_count.
        ls_response-error_count        = 1.

        er_entity = ls_response.
        RETURN.

      ENDIF.

      " PO 문서유형 Prefix와 순번을 조합하여 최종 구매문서 번호를 만든다.
      ls_po_group-po_no = |{ gc_bsart_po }{ lv_nr_number }|.

      " 첫 번째 생성 PO 번호는 별도 응답 필드에 보관한다.
      IF lv_first_po_no IS INITIAL.
        lv_first_po_no = ls_po_group-po_no.
      ENDIF.

      " 생성 PO가 여러 건이면 쉼표로 연결하여 UI5 MessagePopover에서 표시한다.
      IF lv_created_po_nos IS INITIAL.
        lv_created_po_nos = ls_po_group-po_no.
      ELSE.
        lv_created_po_nos = |{ lv_created_po_nos }, { ls_po_group-po_no }|.
      ENDIF.

      " 현재 그룹에 채번된 PO 번호만 LT_PO_GROUP에 반영한다.
      MODIFY TABLE lt_po_group FROM ls_po_group TRANSPORTING po_no.

    ENDLOOP.

    LOOP AT lt_po_group INTO ls_po_group
      WHERE po_no IS INITIAL.

      ls_response-rfq_no             = ls_request-rfq_no.
      ls_response-message_type       = gc_msg_error.
      ls_response-message_text       = |PO Header 그룹의 PO 번호가 정상적으로 채번되지 않았습니다.|.
      ls_response-po_count           = 0.
      ls_response-po_item_count      = 0.
      ls_response-first_po_no        = ''.
      ls_response-created_po_nos     = ''.
      ls_response-skipped_item_count = lv_skipped_count.
      ls_response-error_count        = 1.

      er_entity = ls_response.
      RETURN.

    ENDLOOP.

    " (중략) 채번된 PO 번호로 Header와 Item Internal Table을 구성한다.
```

#### Backend: PR 참조 갱신

```abap
*--------------------------------------------------------------------*
* [13-3] PR 참조 갱신
*--------------------------------------------------------------------*
* BANFN이 있는 PO Item만 PR 갱신 대상이다.
* 수기 RFQ 기반 PO는 BANFN이 없을 수 있으므로 PR 갱신을 생략한다.
*
* 최종 정책:
* - ZTD3MM0015-EBELN = 생성 PO 번호
* - ZTD3MM0015-EBELP = 생성 PO Item
* - 기존 EBELN/EBELP에 MQ 번호가 있더라도 생성 PO 번호로 덮어쓴다.
*
* Gateway 트랜잭션 정책:
* - CREATE_ENTITY 내부에서 직접 ROLLBACK WORK를 수행하지 않는다.
* - 실패 시 Gateway Business Exception을 발생시켜 Framework Rollback에 맡긴다.
*
* 주요 변수와 필드:
* - LT_PO_ITEM       : DB 저장이 완료된 생성 PO Item 목록
* - LS_PO_ITEM       : 현재 원천 PR을 갱신할 PO Item
* - LS_PO_ITEM-BANFN : PO Item이 참조하는 원천 구매요청 번호
* - EBELN / EBELP    : 생성된 PO 번호와 PO Item 번호
* - STATU='C'        : 구매요청 후속처리 완료상태
* - AEDAT/AEZET/AENAM: 최종 변경일, 변경시간, 변경사용자
* - GC_LVORM_OFF     : 삭제되지 않은 유효 PR의 삭제표시 초기값
* - SY-SUBRC         : PR UPDATE 실행 결과 코드
* - SY-DBCNT         : PR UPDATE로 실제 갱신된 Row 수
* - SY-DATUM         : PR 최종 변경일에 저장할 현재 시스템 날짜
* - SY-UZEIT         : PR 최종 변경시간에 저장할 현재 시스템 시간
* - SY-UNAME         : PR 최종 변경사용자에 저장할 현재 SAP 사용자
*
* LS_PO_ITEM Component:
* - LS_PO_ITEM-EBELN : 생성된 PO 번호
* - LS_PO_ITEM-EBELP : 생성된 PO Item 번호
*--------------------------------------------------------------------*
    LOOP AT lt_po_item INTO ls_po_item
      WHERE banfn IS NOT INITIAL.

      " BANFN이 존재하는 PO Item만 원천 PR에 생성 PO 참조를 반영한다.
      UPDATE ztd3mm0015
         SET ebeln = @ls_po_item-ebeln,
             ebelp = @ls_po_item-ebelp,
             statu = 'C',
             aedat = @sy-datum,
             aezet = @sy-uzeit,
             aenam = @sy-uname
       WHERE banfn = @ls_po_item-banfn
         AND lvorm = @gc_lvorm_off.

      IF sy-subrc <> 0 OR sy-dbcnt <> 1.

        " PR은 정확히 1건만 갱신되어야 하며, 그렇지 않으면 Gateway Framework가 전체 Rollback한다.
        RAISE EXCEPTION TYPE /iwbep/cx_mgw_busi_exception
          EXPORTING
            message_unlimited =
                                |PR { ls_po_item-banfn } 갱신 중 오류가 발생했습니다. 갱신 건수 { sy-dbcnt }건입니다. PO 저장을 취소했습니다.|.

      ENDIF.

    ENDLOOP.
```

### 한계 및 개선점

| 현재 한계 | 개선 방향 |
| --- | --- |
| 생산계획과 자재 가용재고를 직접 조회하지 않음 | MRP, 현재고, 안전재고 및 생산오더 요구일 연계 |
| BOM 버전 및 대체자재를 관리하지 않음 | BOM/대체자재 조회 기능과 구매 추천 기준 연계 |
| 판매, 출하, 매출 및 수익성 분석과 직접 연결되지 않음 | 향후 SD/FI 데이터와 PO 원가 정보를 통합 분석 |
| PO 생성 결과가 요약 응답 1건 중심 | 생성된 PO Header 목록과 제외 Item 상세 Dialog 추가 |
| 동시 사용자 중복 생성은 저장 직전 재조회로 방어 | SAP Lock Object 및 Enqueue/Dequeue 적용 |
| 대량 RFQ 데이터 처리 성능 검증이 부족 | SQL Trace, Index, Paging 및 대량 테스트 수행 |
| `sap.ui.table.Table`은 Desktop 사용성이 중심 | Tablet/Phone에서는 Responsive Table 또는 별도 화면 검토 |
| Number Range 채번 후 오류 발생 시 번호가 소모될 수 있음 | 채번 전 검증 강화 및 번호 소모 정책 문서화 |

### 최종 포트폴리오 문장

> 하나의 RFQ에 접수된 여러 공급업체 견적을 오늘 기준 환율과 납기일 기준으로 비교하고, 요청 납기를 준수하면서 KRW 환산총액이 가장 낮은 거래선을 자동추천했습니다. 채택된 견적은 PO 일괄 생성까지 연결하여 필요한 자재의 공급업체와 납기를 빠르게 확정함으로써, 비즈니스 챌린지 1-2인 생산계획 수립 시 자재 조달 가능성 반영 부족 문제를 완화하는 데 기여했습니다.
