## 3. 현재 조회조건 구조

### 기본 조회조건

| 조건 | 모델 필드 | 현재 상태 |
| --- | --- | --- |
| 기준일 | `filter>/KeyDate` | OData `KeyDate`로 전송 |
| 조회기간 | `filter>/LookbackMonths` | UI만 존재, 현재 OData 미전송 |
| 지연 상태 | `filter>/DelayStatuses` | OData `DelayStatus`로 전송 |

### 상세 조회조건

| 조건 | 모델 필드 | OData 전송 |
| --- | --- | --- |
| 자재코드 | `filter>/Matnr` | `Matnr eq ...` |
| 자재명 | `filter>/Maktx` | 현재 미전송 |
| 공급업체 | `filter>/Lifnr` | `Lifnr eq ...` |
| 공급업체명 | `filter>/Name1` | 현재 미전송 |
| 플랜트 | `filter>/Werks` | `Werks eq ...` |
| PR번호 | `filter>/PrNo` | `DocType eq 'PR' and DocNo eq PrNo` |
| RFQ번호 | `filter>/RfqNo` | `DocType eq 'RFQ' and DocNo eq RfqNo` |
| PO번호 | `filter>/PoNo` | `DocType eq 'PO' and DocNo eq PoNo` |

문서번호 조건이 여러 개 입력되면 현재 우선순위는 아래와 같다.

```text
PR번호 > RFQ번호 > PO번호
```

## 4. 지연 상태 필터 정책

화면에는 사용자가 이해하기 쉬운 개별 상태를 표시하고, Backend 전송 직전에 대표 코드로 변환한다.

| 화면 선택 | Backend 전송 |
| --- | --- |
| PR/RFQ/MQ/PO/IV 지연 상태 5개 전체 | `DELAY` |
| PR/RFQ/MQ/PO/IV + 정상 전체 | `ALL` |
| 정상만 선택 | `NORMAL` |
| 일부 상태 다중 선택 | 상태별 개별 조회 후 Frontend 병합 |

기본값은 정상 제외 5개다.

```text
PR_DELAY
RFQ_NO_QUOTATION
MQ_SELECTION_DELAY
PO_DELIVERY_DELAY
IV_INCOMPLETE
```

## 6. 보류 중인 15단계: LookbackMonths

현재 조회기간 버튼은 UI에는 존재하지만 OData로 전송하지 않는다.

이유:

```text
Backend metadata에 LookbackMonths Property가 없을 때
LookbackMonths를 $filter로 보내면 Gateway 400 오류가 발생했음.
```

현재 실제 전송:

```text
KeyDate만 전송
LookbackMonths는 미전송
```

따라서 `최근 3개월`과 `최근 6개월` 선택 결과는 현재 동일할 수 있다.

### Backend에서 해결해야 할 내용

| 작업 | 설명 |
| --- | --- |
| 적용 EntitySet 결정 | 최소 `DashboardSummarySet`, `DelayListSet` 권장 |
| metadata 추가 | 각 EntityType에 `LookbackMonths` 추가 |
| DPC_EXT 필터 파싱 | 없으면 기본 3개월 |
| 기간 계산 | `KeyDate` 기준 최근 N개월 |
| 문서 날짜 기준 결정 | PR/RFQ/PO 기준 문서 생성일 추천 |
| Gateway 테스트 | `LookbackMonths eq 3`, `LookbackMonths eq 6` 비교 |

Backend 반영 후 Frontend에서 아래 두 함수에 전송을 다시 활성화하면 된다.

```js
_buildSummaryFilters()
_buildDelayListFilters()
```

## 9. Row 선택 분기 정책

현재 Row 선택 이벤트는 구현되어 있고, 선택한 문서의 `DocType`, `DocNo`를 view 모델에 저장한다.

다음 단계에서 아래 정책을 구현하면 된다.

| DocType | 동작 |
| --- | --- |
| `PR` | Mid Column 열지 않음. PO Flow 호출 금지. 안내 메시지 표시 |
| `RFQ` | Mid Column 열지 않음. PO Flow 호출 금지. 안내 메시지 또는 RFQ 강조 |
| `PO` | Mid Column 열기. `ProcessFlowSet`, `ProcessItemSet` 조회 |

현재 설계 V1.2.1 기준 Mid Column은 PO 기준 상세 화면이다.

## 11. 주의사항

1. `LookbackMonths`는 아직 Backend 미완료라 Frontend에서 보내면 안 된다.
2. `DashboardSummarySet`, `WeeklySummarySet`에는 상세조건 `Matnr/Lifnr/Werks`를 보내지 않는다.
3. 상세조건 `Maktx`, `Name1`은 현재 OData 필터로 보내지 않는다.
4. PR/RFQ는 현재 PO 상세 Flow 대상이 아니다.
5. Mid Column 구현 시 PO Row에서만 `ProcessFlowSet`, `ProcessItemSet`을 호출해야 한다.
6. 견적 비교 앱과 동일한 정렬/그룹 패턴을 사용했으므로, 추가 수정 시 `ui5/quote_comparison`의 구현을 참고하면 된다.
